## 现在的样子(V27)

**用法**:解压 zip → 进 `video_ocr.dist` → 双击 `video_ocr.exe`(窗口标题里带版本号)。顶栏就这几项:

| 控件 | 默认 | 说明 |
| --- | --- | --- |
| 判定 | **泡泡判定** | 三选一:泡泡判定(V20 起的默认)／结构判定(最慢)／墨水判定 |
| 启用 OCR | 开 | 关掉就只出行、不读字 |
| 选项轨 | 开 | 选项单独一条轨;关掉更快,输出只剩对话行 |
| 需要字形行(治毛领/地面) | **关**(V25 新增) | 关 = 快,白色毛领/云/石板路那类假行会回来;开 = 治假行,代价是慢、单字行会漏 |
| 诊断日志 | 开 | 每 10 秒一行进度,外加每句的 `墨水／峰值／字形` 明细 |

判定阈值(175)、防连读(1.3)在右侧「设置」里,不同片子各调各的。

**圆钮(▶)怎么判**:程序先在 exe 旁边找 `anchor_template.png`。有模板就按"内容区高度的 9.4%"
缩放后匹配(0.55~1.7 倍共 7 档,所以换分辨率不用换模板);**配不上就自动退回形状判据**
(圆环 `fill 0.08~0.45`、近似正方、占内容区高 6.5%~13%)。
**V26 起**:一张模板要是连续试 12 次、最高分都够不到阈值的 70%,程序会判定"它配不上这支片子"
并停用模板匹配(日志里会说明),速度直接回到走形状判据那一档。
**不想用模板,把 `anchor_template.png` 删掉就行** —— V25 起删掉也照样能用形状判据。

**速度参考**(2 小时 1280×720/60fps 的片子,总帧数约 44 万):

| 设置 | 速度 | 同一支片子 |
| --- | --- | --- |
| 默认(不勾"需要字形行") | ~130 帧/秒 | ~50 分钟 |
| 勾上"需要字形行",或模板配不上却还在硬匹配 | ~17~49 帧/秒 | 2.5~7 小时 |

挂机前先看一眼日志里的 `⏱ … 帧/秒`,它自己会算预计剩余时间。

## V27 修了什么:同一框里连续换台词,不再并成一句

**现象**:参考字幕里有、我们这边整条不见的短句(反应声/音效/环境音,如「ざわざわ……」、
「什么！？」「咔嚓！」),复核报告里查不到被删 —— 因为它不是被删的,是**被并进后一句了**。

**原因**(拿视频抽帧量出来的墨水曲线):这些短句后面紧跟一句长台词,而对话框**一次都没空过**,
墨水又只涨不跌(0.036 → 0.061 → 0.119),老的断句规则(框空 5 帧 / 墨水掉到峰值 30% /
画面突变)一条都不触发 → 整段被当成一句,而且只留"墨水最多那一帧"的 OCR = 那句长台词,
短句连它的时长一起被吞。整片实测有 **58 处**,其中 0:29:16、0:41:50 各连吞 3 句。

**V27 的两条新判据**(对称,前提都是"上一句已经写完了"= 墨水静置 ≥12 帧不动,记下水叫 `d_hold`):

- 墨水**涨过 `d_hold` 的 1.5 倍**(且至少 +0.0015)→ 新的一句开始打字 → 断开;
- 墨水**掉到 `d_hold` 的 50% 以下**(且至少 −0.0015)→ 旧字被清掉 → 断开。

打字过程中的正常增量(每帧几个百分点)不会误触发;万一短句逐字打字被拆成两段,
"开头 70% 一致就缝合碎片"那条老规则会把它们接回去。

阈值都拿视频抽帧量过:0:25:12「ざわざわ……」静置 5.3 秒后一帧涨到 1.68 倍 ✓;
0:29:16 那三句(2.9 倍 / 2.7 倍 / 2.3 倍)✓;0:41:50 掉 55% ✓。

## V26→V22 都改了什么(压缩版)

- **V26**:模板"自杀开关"(见上),标题去掉"结构判定版"遗留标签,⏱ 行加了"近段速度"。
  只提速,判定一个字没改;
- **V25**:「需要字形行」默认**关**,并做成界面开关(V24 是常开 → 又慢又扫不出东西);
  新增**墨水上限**(墨水 >60% 的帧直接判"不是泡泡",后面贵的计算全跳过);
  模板配不上时**真的会**退回形状判据 —— 这是 V22 就该有的退路,但 V22~V24 里它是**死代码**
  (模板文件总存在,回退分支永远走不到),是 V24"选项全丢"的根因之一;模板缩放档 3 → 7 档;
- **V24**:把"泡泡 = 浅色平整 + 有墨水 + **有一行字**"这条判据做成常开 —— 事后看是一次退步(见 V25 那三条);
- **V23**:`find_anchor` 里的"局部背景亮度"从 165×165 高斯换成**方框模糊**(走积分图,每像素 O(1))——
  高斯哪怕分离实现也要几十毫秒,这是流水线里最贵的一笔(V22 实测约 3.7 倍慢主要就是它),判定逻辑不变;
- **V22**:修了一个从引入起就存在的真 bug —— 圆钮判定条件**写反了**:旧代码 `fill >= 0.55` 只收
  "实心暗块",而真圆钮是"空心环"(实测 `fill` 0.12~0.13),于是专挑立绘的帽子/头发、专排真圆钮。
  现在改成 `fill 0.08~0.45`;同时引入模板匹配。

**这一版的原则:宁可多,不可漏。** 多出来的行在 Aegisub 里一眼就能删掉,漏掉的行你
根本不知道它存在过 —— 所以判据一律往"不漏"那边调。

## V21 改了什么（只提速，判定逻辑一个字没改）

1 小时片子跑了 1 小时才一半，先算清账：**慢的从来不是 OCR**（每句话才调一次，全片一千
多次），而是两笔"每帧"的开销，而且都是我自己加的：

1. **圆钮检测降频**：每 3 帧找一次，中间帧沿用上次结果（圆钮是静止的）。`find_anchor`
   要在一片很大的区域上做高斯模糊 + 连通域，是每帧最贵的一笔 —— 这一项省掉约 **2/3**；
2. **泡泡平整度改成"先看墨水、再验平整"**：没墨水的帧直接跳过（绝大多数帧都没墨水），
   有墨水才去算；算法也换成 OpenCV 的 HSV 取亮度 + 只抽 1/4 像素算分位 → 省掉绝大部分；
3. **挂机友好**：日志每 10 秒打一行 `⏱ 已跑 37.2% / 41 帧每秒 / 预计剩余 52 分`，
   一眼就知道要不要继续等；
4. 顺带说明：**显卡红灯亮不亮是解码器有没有用硬件解码**（帧是成批解的），
   不能当进度指示；真正的进度看进度条和日志。

如果只想最快：用「泡泡判定」+ 取消勾选「选项轨」（后者每帧都要找圆钮）。
「结构判定」是最慢的（每帧都要找一遍字形连通域）。

## V20 改了什么(1 小时片子的教训：V19 把选项轨掐死了)

V19 我加了"选项必须 OCR 读出日文"这条硬条件，结果 **1 小时片子里只活下来 2 条选项**，
而你对照完整 SRT 能看到有很多选项 —— 真选项只要锁定那一帧没读出来，整段就没了。
这说明我在两个极端之间来回摆：V17 满江红、V19 全掐死。这次换回**原版真正管用的那一点**：

1. **新增「泡泡判定」并设为默认**（界面下拉框第一项）：框里必须是**一大片平整的浅色泡泡**
   而且有墨水。这是原版"米色占比"判据的加强版——多加了一条**"泡泡内部颜色必须是平的"**：
   - 天空有渐变、沙地有花纹、立绘和糖果花里胡哨 → 都过不了；
   - 它**不看字数**，所以两个字的短句也算（不会再出现"短句被整个删掉"的老毛病）；
   - 原版能对准气泡，靠的就是这个米色判据；这一版只是把它做扎实。
2. **选项轨不再要求"必须读出日文"**：现在 **泡泡 + 墨水 +（圆钮 或 文字行）** 就算一行选项。
   读得出文字就带上文字，读不出就留 `Line N [Choice]` 占位行——**至少时间对得上**，
   你在 Aegisub 里照着时间补字比我猜要靠谱。
3. **三种判据都在界面下拉框里**（泡泡判定 / 结构判定 / 墨水判定），哪个顺手用哪个，
   不用重新编译。回退的路一直留着。

## V19 改了什么(按你最新的话:**删多余行比漏一两个更闹心**)

先把账说清楚：V16 输出 112 条（比参考稿多 7 条），V18 输出 124 条（多 19 条）
—— **多出来的 12 条全是我放回来的 choice 行**，对话轨一个字没动。所以罪魁祸首只有选项轨。

1. **选项轨只输出"读得出日文"的选项**：结构判据 + 圆钮 + **OCR 必须读出假名/汉字**，
   三者齐了才写一行 `文字 [Choice]`；读不出文字的整段直接丢掉，不再产出 `Line N [Choice]`。
   依据是实测的：真实选项（1:13 的「信じられない」）读得出来，而 40 张假选项的候选图
   **一张都读不出文字** —— 这一条能一次性把"满江红"清掉。
2. **「选项轨」开关放到界面上了**（顶栏，默认勾上）：不想跑就取消勾选，不用去改 json。
   你说"没看到 UI 哪里可以关"——是我把它塞进 config 了，而从压缩包临时目录跑时那个 json
   每次都是新生成的，等于没用，这是我的疏忽。
3. 对话轨（空白 `Line` 行）保持 V16 那套不动：那是你还能接受的量（7 分钟约 7~10 条），
   而且它们显眼、好删。

如果你觉得**连缓冲都不要**，还可以在界面上取消「选项轨」，那样整条选项轨不跑，
输出就只有对话行，和 V16 一模一样、还更快。

## V18 修了什么(对着 V17 那轮的问题)

1. **选项段长得离谱**（12 条里 7 条：97 秒、60 秒、46 秒、39 秒…，把中间的对话全包进去）。
   原因是我把对话框默认判据改成"墨水判定"时，**选项轨也跟着松了**：它变成"背景里有墨水
   就算选项还在"，在那种花花绿绿的背景上永远关不掉。现在选项轨**固定用结构判据**
   （框里得真有一行字 + 文字坐在气泡底色上），不跟着「判定」下拉框走。
2. **"选项还在"的定义改了**：= 框里有文字行 **且** 圆钮还在（以前只看墨水/文字的布尔值）。
   另外加了一道保险丝：**超过 12 秒的选项段强制结算**。
3. **新增 `use_choice_track` 开关**：嫌选项轨吵，就在 config 里设成 `false`，整条选项轨不跑
   （速度也会快不少）。
4. **OCR 多帧补救按你的要求取消**（`retry_ocr_frames: 0`）：短句就留空白 `Line` 行，不猜。
   以后想再试，把它设成 4 就恢复了。
5. **复核窗口的毛病**：连点只开一个窗口（V17 会开出好几个）；选完文件会把窗口抬回前面
   （V17 里它会躲到主窗口后面，看着像被关掉了）；跑完会弹提示，不用傻等。
6. **复核选项行改用「选项框」去核**：V17 用对话框的框去核选项行，周围的对话替它作证，
   结果 12 条假选项只揪出 1 条。
7. **复核别再误删真短句**：V17 复核用的是打轴那套"至少要 3 个字"的判据，于是两个字的气泡
   （比如「嗯？」）被判成空行删掉了。现在复核**单独用一套更松的判据**（2 个字就算有字），
   而且 OCR 投票从"只投前 2 帧"改成"抽到的帧都投"。
8. **太短的行一律不删**（默认 < 0.6 秒）：证据不足的行只在报告 D 节列出来让你看。
   这三个数都在 config 里：`check_min_glyphs` / `check_ocr_frames` / `check_min_seconds`。

## V17 新增

1. **选项标记回归**：读不出文字的选项段也会输出 `Line N [Choice]`（方便你人工定位），
   OCR 读到文字就带上文字。V16 的"读不出就整段丢弃"太狠，把 1:13 那处也丢了。
   只有选项轨自己扫出来的行才带 `[Choice]`，对话框轨的误触发不会带——两者一眼能分清。
2. **OCR 补救**：有些句子"墨水最多那一帧"正好是空气泡（实测确实有，比如 #60 #88），
   OCR 自然是空的。现在扫描结束后会在**那一句自己的时间范围内**换几帧重试，
   把"真台词却变成 `Line N`"的尽量补回来。
3. **🔍 复核（视频 + SRT）**：主界面左上角的新按钮，打开一个小窗口：
   - 逐条跳到它自己的时间里抽 3~4 帧，判断"框里到底有没有文字"；
   - 判据 = **文字行结构 + 文字坐在气泡底色上 + OCR 读不读得出**，三者都否才判可疑；
     所以"画面上有字、只是 OCR 没读出来"的短句不会被误判；
   - 三种方式，你选：
     - `只报告`（默认）→ 出一份 `<名字>_check.txt` 清单 + 可疑行截图文件夹；
     - `只报告+标记版SRT` → 再另存一份 `<名字>_check.srt`，可疑行前面加 `[?]`，
       你直接在 Aegisub 里按时间轴过一遍最直观；
     - `报告+删掉空行` → 直接生成清理后的 SRT（原文件自动存成 `.bak`）。
   - **带 `[Choice]` 的行永远不会被删**，只在报告里单列一节让你看。
   - 复核用的是**当前界面上的框、阈值、判定方式**，所以复核时保持和打轴时一致。

## V16 修了什么

1. **对话框默认改回 V12 的"墨水判定"**。V15 用的结构判据要求"至少 3 个字形 +
   占框宽 25%",2~4 个字的短句天生达不到。我拿你那版翻译稿逐条比了一遍:这 7 分钟里
   翻译稿 105 条、V15 只输出 99 条,**少掉的 12 条全是短句**(「硬糖!?」「嗯?」
   「那是……什么来着?」「不要不要不要~!!」),连 `Line N` 占位都没留下。
   现在默认只数墨水 —— 短句照样成行,顶多 OCR 读不出、留个占位行给你手补。
   想更干净可以在「判定」下拉框切回 **结构判定**（会漏短句，但假行少）。
2. **墨水判据现在跟着界面上的阈值滑杆走**（V15 的 legacy 模式写死用配置里的值，
   你拉滑杆它不动）。
3. **选项多一道"像不像日语"的过滤**：从背景招牌读出来的 `f1NISH`、`)0`、`,ノ`、`すR`
   这类垃圾全部丢掉（真选项都是假名）。
4. **选项的时间对齐**：锁定成功时把开始时间挪到"这个静止窗口的开头"，不再把前面被
   误判的十几秒一起算进去（你那条 1:13 的选项之前被拉成了 55s~77s）。

## V15 修了什么(对着你上一轮反馈的三件事)

1. **拖放失效** —— `install_drop_target` 里 ctypes 把函数指针 `cast` 成 `c_ssize_t`，
   而 `cast` 的第二个参数必须是指针类型，于是直接抛异常、拖放整块失效
   （日志里那句 `⚠️ 拖拽: 不可用(用按钮加载也一样)` 就是它）。已改成 `c_void_p`，
   并补上 `GetParent` 的 restype（不然 64 位下句柄会被截断）。
2. **碎句（同一句被切成两三条）** —— 这是打字机效果 + 灵敏度 1.3 共同造成的：
   每多打出一个字，ROI 里的墨水就变一次，超过 1.3% 就触发"变化切断"。
   现在**墨水正在增长的那些帧不算换句**，要连续 3 帧墨水不再增长才允许按画面变化切断。
   同时把"缝合"从"必须完全相等"放宽成**开头 70% 一致就合并，并保留更长的那句**。
3. **选项还是一堆无效行** —— 我把你 `_review/ocr_fail/` 里那 40 张失败图拼出来看了：
   **全是糖果装饰、背景和立绘**（护目镜、脸、黑影人物），**一张有文字的都没有**。
   所以选项改成：**锁定那一刻就试一次 OCR**，读不出字说明这不是真选项（立绘能骗过形状
   判定，但骗不过 OCR），**不锁定、继续等下一个静止瞬间**；整段都读不出文字就直接丢弃，
   不再输出 `Line N [Choice]`。真选项（比如 1:13 那处）会被读出来并保留。

   事件循环"，结果 Windows OCR 大部分时候返回空字符串。你那份复核报告里
   **165 条有 136 条是"判定强 + OCR无文本"**，而我把那些候选帧图拼出来一看，

3. **"选项框我还没理解要框住哪个范围"** —— 见下面「三个框怎么摆」。
4. **"判定和复核不知道是啥"** —— 下拉框改成中文了，含义见「界面上的控件」。
5. **"下次加拖放"** —— 加了：视频文件直接拖进窗口就加载，画面中央也写了提示。
6. 顺手修掉一个 60fps 相关的坑：原来"连续 2 帧认不出文字就算说完一句"，
   在 60fps 下只有 33ms，会把一句台词切得比 30fps 碎很多。现在按秒换算
   （默认 0.08 秒），并会把换算结果打进日志。

## 三个框怎么摆

- **对话框(绿)**：框住**台词文字那一块**，也就是浅色气泡里写字的横条。
  你的做法一直是对的（不含名牌、不含 AUTO），保持就行。
  两条台词都在气泡里的话，框高一点把两行都包进去也没关系。
- **选项框(蓝)**：框住**一条选项的文字**，一般就框**最上面那条**。
  - 只框一条。两条一起框 → 程序会当成一行，两句话粘在一起。
  - 左边那个棕色圆钮**框不框进去都行**：程序读 OCR 时会自动把它排除，
    但判定"这是不是选项"时反而要用到它（要能在框的左边/上下找到它）。
  - 高度大致＝气泡文字高 + 一点余量就行。
  - 平时这一格是空的、不会误触发：判定要求"框里出现一行字形 + 左边找到圆钮 +
    文字周围是浅色气泡"三条同时成立。
- **不需要再画背景框**（V12 的那个红框已经删掉了）。

## 界面上的控件

- **判定**：用哪种方式判断"这一帧有没有一行文字"。
  `结构判定`=新的字形判据（默认，推荐）；`传统判定`=V12 的老判据（只数墨水），
  出问题时可以切回来对比。
- **复核**：处理完要不要拿更严格的判据再看一遍候选帧。
  `关闭` / `只报告`（默认，推荐先这样）/ `报告并删除`——只有"严格判据认不出文字
  而且 OCR 也没读出文本"才会删，并且原始 SRT 会存成 `.bak`。
- **防连读灵敏度**：越小越容易切断（拉高 = 少碎句但容易把两句粘一起）。默认 1.3。
- **文字/边缘 阈值**：TWST 也生效了，默认 175，可调 110-240。它只影响"能不能判出
  有文字"，不影响 OCR 的输入。
- **诊断日志**：勾上后每行都会打印 idx/时长/墨水/峰值/字形数，以及每次 OCR 用了
  哪块图、读到了什么。调参基本靠它。

## 出问题怎么反馈

把这三样发出来就够：

1. 运行日志里带 `└ idx=` 的行 + 带 `✎ OCR` / `⚠️ OCR没读出` 的行；
2. `<视频名>_review.txt`（哪几条被判可疑、为什么）；
3. 如果 `_review/ocr_fail/` 里有图，挑几张代表性的。

## 参数速查（exe 旁边的 video_ocr_config.json，改完重启即可，不用重新编译）

- `drop_unreadable_choice`（true）：选项段读不出文字就丢掉。**假选项多就保持 true**；
  万一真选项被丢掉（日志里会有 `🗑️ 丢弃…` 那行），改成 false 就退回输出占位行。
- `motion_cut_stable_frames`（3）：墨水连续几帧不再增长才允许按画面变化切断。
  调大 = 打字机更难切碎（代价是换句反应迟钝一点）。
- `merge_prefix_ratio`（0.7）：相邻两条台词开头有多少比例一致就合并成一条。
- `bg_pale_ratio_min`（0.5）：文字周围要多"浅色"才算坐在气泡上。假 choice 多就往上调
  （0.6~0.7），真台词漏检就往下调（0.35）。
- `bg_pale_v_min`（140）/ `bg_pale_s_max`（90）：上面那条"浅色"的定义，跟着游戏配色调。
- `min_glyphs`（3）：一行至少几个字才算文字行。漏短句就降到 2，假阳性多就升到 4。
- `glyph_fill_max`（0.62）：字形填充率上限，实心色块靠它排除。
- `glyph_width_cv_min`（0）：打开（例如 0.18）会加一条"一排宽度不能太整齐"的检查，
  专治书架/栅栏/砖墙。
- `anchor_fill_min`（0.55）：圆钮判定的松紧。认不到圆钮就降，认到奇怪的圆就升。
- `ocr_crop_to_text`（true）：允许用"文字行紧缩图"喂 OCR。取图顺序写死在代码里：
  对话框先整框（V12 的做法最可靠），选项框先紧缩图（顺手排除圆钮），两者互为备胎。
  关掉它就一律用整框。
- `ocr_upscale_min_height`（96）：OCR 前把小图放大到至少这么高再识别。

## 已知风险

- 结构判据仍可能把"一排规则的小方块"当文字（书架书脊、栅栏、砖墙、台阶）。
  靠 `glyph_fill_max` / `glyph_width_cv_min` 抑制，复核轮的严格判据也会标出来。
- 极短台词（1-2 个字）凑不成"一排"，仍然会落成 `Line N` 占位行（有意保留，方便定位）。
- 紧缩图有时会把一句话裁掉一截，所以对话框默认改用整个框；选项框仍然优先紧缩图
  （为的是把圆钮排除掉），如果一个长选项被裁短，把这个轨道也改成先整框即可。
