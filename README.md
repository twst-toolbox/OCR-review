# Video Subtitle Extractor V16

TWST / 18T 打轴 & Windows 自带 OCR 辨识。

**这一版的原则:宁可多,不可漏。** 多出来的行在 Aegisub 里一眼就能删掉,漏掉的行你
根本不知道它存在过 —— 所以判据一律往"不漏"那边调。

## V17 新增

1. **选项标记回归**：读不出文字的选项段也会输出 `Line N [Choice]`（方便你人工定位），
   OCR 读到文字就带上文字。V16 的"读不出就整段丢弃"太狠，把 1:13 那处也丢了。
   只有选项轨自己扫出来的行才带 `[Choice]`，对话框轨的误触发不会带——两者一眼能分清。
2. **OCR 补救**：有些句子"墨水最多那一帧"正好是空气泡（实测确实有，比如 #60 #88），
   OCR 自然是空的。现在扫描结束后会在**那一句自己的时间范围内**换几帧重试，
   把"真台词却变成 `Line N`"的尽量补回来。
3. **🔍 复核（视频 + SRT）**：主界面左上角的新按钮，打开一个小窗口：
   - 逐条跳到它自己的时间里抽 3~4 帧，判断"框里到底有没有文字"；
   - 判据 = **文字行结构 + 文字坐在气泡底色上 + OCR 读不读得出**，三者都否才判可疑；
     所以"画面上有字、只是 OCR 没读出来"的短句不会被误判；
   - 三种方式，你选：
     - `只报告`（默认）→ 出一份 `<名字>_check.txt` 清单 + 可疑行截图文件夹；
     - `只报告+标记版SRT` → 再另存一份 `<名字>_check.srt`，可疑行前面加 `[?]`，
       你直接在 Aegisub 里按时间轴过一遍最直观；
     - `报告+删掉空行` → 直接生成清理后的 SRT（原文件自动存成 `.bak`）。
   - **带 `[Choice]` 的行永远不会被删**，只在报告里单列一节让你看。
   - 复核用的是**当前界面上的框、阈值、判定方式**，所以复核时保持和打轴时一致。

## V16 修了什么

1. **对话框默认改回 V12 的"墨水判定"**。V15 用的结构判据要求"至少 3 个字形 +
   占框宽 25%",2~4 个字的短句天生达不到。我拿你那版翻译稿逐条比了一遍:这 7 分钟里
   翻译稿 105 条、V15 只输出 99 条,**少掉的 12 条全是短句**(「硬糖!?」「嗯?」
   「那是……什么来着?」「不要不要不要~!!」),连 `Line N` 占位都没留下。
   现在默认只数墨水 —— 短句照样成行,顶多 OCR 读不出、留个占位行给你手补。
   想更干净可以在「判定」下拉框切回 **结构判定**（会漏短句，但假行少）。
2. **墨水判据现在跟着界面上的阈值滑杆走**（V15 的 legacy 模式写死用配置里的值，
   你拉滑杆它不动）。
3. **选项多一道"像不像日语"的过滤**：从背景招牌读出来的 `f1NISH`、`)0`、`,ノ`、`すR`
   这类垃圾全部丢掉（真选项都是假名）。
4. **选项的时间对齐**：锁定成功时把开始时间挪到"这个静止窗口的开头"，不再把前面被
   误判的十几秒一起算进去（你那条 1:13 的选项之前被拉成了 55s~77s）。

## V15 修了什么(对着你上一轮反馈的三件事)

1. **拖放失效** —— `install_drop_target` 里 ctypes 把函数指针 `cast` 成 `c_ssize_t`，
   而 `cast` 的第二个参数必须是指针类型，于是直接抛异常、拖放整块失效
   （日志里那句 `⚠️ 拖拽: 不可用(用按钮加载也一样)` 就是它）。已改成 `c_void_p`，
   并补上 `GetParent` 的 restype（不然 64 位下句柄会被截断）。
2. **碎句（同一句被切成两三条）** —— 这是打字机效果 + 灵敏度 1.3 共同造成的：
   每多打出一个字，ROI 里的墨水就变一次，超过 1.3% 就触发"变化切断"。
   现在**墨水正在增长的那些帧不算换句**，要连续 3 帧墨水不再增长才允许按画面变化切断。
   同时把"缝合"从"必须完全相等"放宽成**开头 70% 一致就合并，并保留更长的那句**。
3. **选项还是一堆无效行** —— 我把你 `_review/ocr_fail/` 里那 40 张失败图拼出来看了：
   **全是糖果装饰、背景和立绘**（护目镜、脸、黑影人物），**一张有文字的都没有**。
   所以选项改成：**锁定那一刻就试一次 OCR**，读不出字说明这不是真选项（立绘能骗过形状
   判定，但骗不过 OCR），**不锁定、继续等下一个静止瞬间**；整段都读不出文字就直接丢弃，
   不再输出 `Line N [Choice]`。真选项（比如 1:13 那处）会被读出来并保留。

## 上一版(V14)修了什么

1. **"OCR 看不到、丢失很多"** —— 找到了：V13 我把 OCR 的 `asyncio.run` 改成"复用同一个
   事件循环"，结果 Windows OCR 大部分时候返回空字符串。你那份复核报告里
   **165 条有 136 条是"判定强 + OCR无文本"**，而我把那些候选帧图拼出来一看，
   `L0006`(604×38) 是干干净净的「ドロップ・タイムから消えた主人公の」——
   字明明在那儿，OCR 却什么都没返回。已退回 V12 的写法。
2. **"有大量的 choice，应该只在 1:13 有一处"** —— 我看了你存下来的图：`L0005/L0008/L0009/L0040`
   全是立绘的头发、护目镜、糖果装饰。原因是判定只要求"框里有一排小字形"，
   而这些东西也能凑成"一排"。现在加了一条硬条件：**文字必须坐在气泡底色上**
   （笔画周围要够浅、够不花；白字模式反过来要求够暗）。真台词都坐在浅色气泡上，
   立绘和背景装饰不是，这一条能把假 choice 砍掉绝大多数。
3. **"选项框我还没理解要框住哪个范围"** —— 见下面「三个框怎么摆」。
4. **"判定和复核不知道是啥"** —— 下拉框改成中文了，含义见「界面上的控件」。
5. **"下次加拖放"** —— 加了：视频文件直接拖进窗口就加载，画面中央也写了提示。
6. 顺手修掉一个 60fps 相关的坑：原来"连续 2 帧认不出文字就算说完一句"，
   在 60fps 下只有 33ms，会把一句台词切得比 30fps 碎很多。现在按秒换算
   （默认 0.08 秒），并会把换算结果打进日志。

## 三个框怎么摆

- **对话框(绿)**：框住**台词文字那一块**，也就是浅色气泡里写字的横条。
  你的做法一直是对的（不含名牌、不含 AUTO），保持就行。
  两条台词都在气泡里的话，框高一点把两行都包进去也没关系。
- **选项框(蓝)**：框住**一条选项的文字**，一般就框**最上面那条**。
  - 只框一条。两条一起框 → 程序会当成一行，两句话粘在一起。
  - 左边那个棕色圆钮**框不框进去都行**：程序读 OCR 时会自动把它排除，
    但判定"这是不是选项"时反而要用到它（要能在框的左边/上下找到它）。
  - 高度大致＝气泡文字高 + 一点余量就行。
  - 平时这一格是空的、不会误触发：判定要求"框里出现一行字形 + 左边找到圆钮 +
    文字周围是浅色气泡"三条同时成立。
- **不需要再画背景框**（V12 的那个红框已经删掉了）。

## 界面上的控件

- **判定**：用哪种方式判断"这一帧有没有一行文字"。
  `结构判定`=新的字形判据（默认，推荐）；`传统判定`=V12 的老判据（只数墨水），
  出问题时可以切回来对比。
- **复核**：处理完要不要拿更严格的判据再看一遍候选帧。
  `关闭` / `只报告`（默认，推荐先这样）/ `报告并删除`——只有"严格判据认不出文字
  而且 OCR 也没读出文本"才会删，并且原始 SRT 会存成 `.bak`。
- **防连读灵敏度**：越小越容易切断（拉高 = 少碎句但容易把两句粘一起）。默认 1.3。
- **文字/边缘 阈值**：TWST 也生效了，默认 175，可调 110-240。它只影响"能不能判出
  有文字"，不影响 OCR 的输入。
- **诊断日志**：勾上后每行都会打印 idx/时长/墨水/峰值/字形数，以及每次 OCR 用了
  哪块图、读到了什么。调参基本靠它。

## 出问题怎么反馈

把这三样发出来就够：

1. 运行日志里带 `└ idx=` 的行 + 带 `✎ OCR` / `⚠️ OCR没读出` 的行；
2. `<视频名>_review.txt`（哪几条被判可疑、为什么）；
3. 如果 `_review/ocr_fail/` 里有图，挑几张代表性的。

## 参数速查（exe 旁边的 video_ocr_config.json，改完重启即可，不用重新编译）

- `drop_unreadable_choice`（true）：选项段读不出文字就丢掉。**假选项多就保持 true**；
  万一真选项被丢掉（日志里会有 `🗑️ 丢弃…` 那行），改成 false 就退回输出占位行。
- `motion_cut_stable_frames`（3）：墨水连续几帧不再增长才允许按画面变化切断。
  调大 = 打字机更难切碎（代价是换句反应迟钝一点）。
- `merge_prefix_ratio`（0.7）：相邻两条台词开头有多少比例一致就合并成一条。
- `bg_pale_ratio_min`（0.5）：文字周围要多"浅色"才算坐在气泡上。假 choice 多就往上调
  （0.6~0.7），真台词漏检就往下调（0.35）。
- `bg_pale_v_min`（140）/ `bg_pale_s_max`（90）：上面那条"浅色"的定义，跟着游戏配色调。
- `min_glyphs`（3）：一行至少几个字才算文字行。漏短句就降到 2，假阳性多就升到 4。
- `glyph_fill_max`（0.62）：字形填充率上限，实心色块靠它排除。
- `glyph_width_cv_min`（0）：打开（例如 0.18）会加一条"一排宽度不能太整齐"的检查，
  专治书架/栅栏/砖墙。
- `anchor_fill_min`（0.55）：圆钮判定的松紧。认不到圆钮就降，认到奇怪的圆就升。
- `ocr_crop_to_text`（true）：允许用"文字行紧缩图"喂 OCR。取图顺序写死在代码里：
  对话框先整框（V12 的做法最可靠），选项框先紧缩图（顺手排除圆钮），两者互为备胎。
  关掉它就一律用整框。
- `ocr_upscale_min_height`（96）：OCR 前把小图放大到至少这么高再识别。

## 已知风险

- 结构判据仍可能把"一排规则的小方块"当文字（书架书脊、栅栏、砖墙、台阶）。
  靠 `glyph_fill_max` / `glyph_width_cv_min` 抑制，复核轮的严格判据也会标出来。
- 极短台词（1-2 个字）凑不成"一排"，仍然会落成 `Line N` 占位行（有意保留，方便定位）。
- 紧缩图有时会把一句话裁掉一截，所以对话框默认改用整个框；选项框仍然优先紧缩图
  （为的是把圆钮排除掉），如果一个长选项被裁短，把这个轨道也改成先整框即可。
