# Video Subtitle Extractor V13「结构判定版」

TWST / 18T 打轴 & Windows 自带 OCR 辨识。V13 相对 V12 的改动:

1. **阈值滑杆接进 TWST**(V12 里黑字分支的阈值是写死的 150,滑杆只在 18TRIP 和预览里生效),
   默认值 175、可调范围 110-240。它只影响"有没有文字"的判定,不改变 OCR 的输入。
2. **判定方式换成"文字行结构"**:在框里找一排高度相近、落在同一条基线、笔画细的小字形。
   不再用"区块浅色占比" —— 实测那张选项帧里,全画面约 1/3 的像素都满足老判据的"浅色",
   它区分不出气泡和背景,这才是选项乱码和换场景乱出空行共同的原因。
3. **选项判定 = 圆钮 + 行内有文字**:在你框的左边和上下找那个"棕色底黑箭头"圆钮,
   找到且在框里认出文字才算一行选项。背景(红框)那一整套删掉了。
4. **切断门槛改成相对值**(相对本句自己的墨水峰值),换视频/换亮度不用重调。
5. **区域改成内容区百分比**:滑杆 + 数字框都能改;自动识别上下黑边(录屏常见),
   百分比按去黑边后的内容区算。
6. **进度条/时间轴**:显示时间码、可输入 `90` / `1:30` / `01:02:03` 跳转、点进度条跳转;
   拖滑杆不再重新解码(H.264 每次 seek 都要从关键帧重解,那是卡顿的根源)。
7. **复核轮**:处理完连图带表列一份可疑行报告,默认只报告不删;
   选 `report+delete` 才会删除"严格判据认不出文字 且 OCR 也没出文本"的行,并自动备份 `.bak`。
8. **参数集中在 `video_ocr_config.json`**(首次运行自动生成在 exe 旁边),改了重启即可生效,
   不用重新编译 —— 这是给远程调参留的后门。
9. 版本号/日期由 CI 注入,窗口标题、Release 名、zip 文件名、tag 里都能看到。

## 怎么用

1. 加载视频 → 切到「对话框(绿)」标签调好文字框,切到「选项框(蓝)」调好选项文字框。
   滑杆前面能看到程序实际算出来的笔画叠加(当前标签页那个框),调完直接看效果。
2. 模式选 TWST(黑字)。判定保持 `structure`,复核先用 `report`。
3. 勾「启用 OCR」「诊断日志」→ 开始处理。
4. 处理完看 `<视频名>_review.txt` 和 `<视频名>_review/` 里的截图:
   哪些行被判可疑、为什么。觉得判据靠谱了再切 `report+delete`。

## 出问题怎么反馈

把 ①运行日志里带 `└ idx=` 的那些诊断行、②`_review.txt` 的前几十行 发出来即可。
如果是"误判成文字"或"漏判",日志里能直接看到当时的字形数、墨水量、圆钮有没有找到,
多数情况下改 `video_ocr_config.json` 里的几个数就能修,不用重新编译:

- `min_glyphs` 3→2:短句更容易被判出来(也更容易误判)。
- `glyph_width_cv_min` 0→0.18:打开"一排宽度不能太整齐"的检查,专治书架/栅栏/砖墙。
- `glyph_fill_max` 0.62→0.5:更严格地排除实心色块。
- `anchor_fill_min` 0.55:圆钮认不出来时往下调;认到奇怪的圆时往上调。
- `bin_threshold_twst`:文字/边缘阈值,和界面滑杆是同一个数。

## 已知风险(写在这里免得以后忘)

- 结构判据可能把"一排规则的小方块"当文字:书架的书脊、栅栏、砖墙、台阶。
  靠 `glyph_fill_max` / `glyph_width_cv_min` 抑制,复核轮的严格判据也会把它们标出来。
- 极短台词(1-2 个字)凑不成"一排",仍然会落成 `Line N` 占位行(这是有意保留的行为,方便定位)。
- OCR 精度相关的手段(放大、多帧投票、错字表、与正文本对齐)**本版没做**,按需求后置。
